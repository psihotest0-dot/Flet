## 2. Договор с бекенда (за ориентация)
- База `http://localhost:8080` (след задача 3 в бекенда слуша само на `127.0.0.1`); всяка заявка носи `X-User-ID: <uuid>`. Токен **няма** (решено).
- `GET /messages?session_id=<id>&limit=<n>` — по подразбиране `limit=50`, максимум 200; отговорът е **от старо към ново**. Съобщение:
  `{id, user_id, session_id, role, content, created_at, sources?: [...]}`. `sources[]`: `{chunk_id, file_name, page_number?, content_snippet, score (0–100), score_type ("cosine"|"rrf"), source_type ("memory"|"concept"|"text"|"ocr")}`.
- `POST /chat/stream` (SSE): първо `event: sources` (JSON масив); после `data: {"reasoning_content": "..."}` и/или `data: {"content": "..."}`; край `data: [DONE]`;
  грешка = `event: error` с `{"error": "..."}`. `POST /chat/regenerate` — същият формат. **Мисленето се скрива във Flet и така остава** (клиентът игнорира `reasoning_content`).
- Памет: `content` ≤ 32 000 знака, `status` ∈ {candidate, active, superseded}, `importance` **1–10** (0 → 400).
- Файлове: лимит 100 MB (= `MAX_UPLOAD_SIZE`). Обработват се: `txt md csv json yaml yml log html htm pdf docx xlsx epub` и изображения (OCR). Всичко друго се качва, но ингестът завършва със статус `failed`.
  Дубликат (същият хеш) → **409** с тялото на вече съществуващия файл.
- Категории: `medicine economics programming law psychology literature general`; `PATCH /v1/files/{id}/category` с `{"category": "..."}`.
- Грешките на бекенда са обикновен текст (`http.Error`), не JSON.
