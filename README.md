# Flet Client for AI Agent

Това е десктоп клиентско приложение, базирано на Flet, предназначено за работа с AI агент.

## Функционалности на приложението
Приложението предоставя следните основни възможности:

- **Глобални настройки (Settings):** Достъпни чрез иконата със зъбно колело в лентата на приложението. Позволяват промяна на `Base URL` (адреса на бекенда): приема се само адрес с `http://` или `https://`, без интервали и без краен `/`, а бутонът „Провери връзката“ показва дали бекендът отговаря на въведения адрес още преди запазване. Диалогът показва и `user_id` само за четене (с бутон „Копирай“) — това е ключът към историята, паметта и файловете в бекенда (нужен е и за Telegram `/link`), затова пази `settings.json`. Полето „Име в чата“ (`display_name`, по подразбиране „Ти“, до 40 знака) е името, с което са подписани твоите съобщения; смяната му важи веднага и за вече показаните съобщения. Бекендът не изисква токен. Настройките се запазват локално.
- **Чат интерфейс (ChatView):** Интерактивен чат с AI асистента (Лили). Поддържа визуализиране на отговори в реално време чрез SSE (Server-Sent Events), както и показване на източници (RAG) в удобен долен панел (BottomSheet), ако такива са предоставени от бекенда. Можете да спрете генерирането на отговора по всяко време.
- **Управление на паметта (MemoryView):** Табличен изглед на всички "спомени", запазени за текущия потребител. Позволява филтриране по статус (напр. `active`, `candidate`), редактиране на съдържанието им директно в таблицата (inline edit) и изтриване на спомени.
- **Управление на файлове (FilesView):** Интерфейс за качване на файлове в системата. Поддържа преглед на статуса на качените файлове (дали са обработени) чрез периодично обновяване, както и възможност за изтриване на съществуващи файлове. Колоната „Вектори" показва състоянието на индексирането (`Изчаква`, `Обработва се`, `Готово · N части`, `Няма текст`, `Грешка`) и позволява с един поглед да се види дали файлът реално участва в търсенето – файл със статус `Няма текст` е обработен, но не може да бъде намерен от RAG търсенето.
- **Индикатор за връзка:** В горния ляв ъгъл до заглавието има индикатор (цветна точка), който показва в реално време дали има успешна връзка към бекенда (зелено) или връзката е прекъсната (червено).

## Архитектура на проекта
Проектът следва стриктна структура с разделение на отговорностите:
- **`api/`**: Съдържа логиката за комуникация с бекенда. Всички HTTP заявки минават изключително през `api/client.py`, използвайки `httpx.AsyncClient` за асинхронна комуникация.
- **`views/`**: Съдържа потребителския интерфейс (UI), разделен на отделни изгледи (Views):
  - **ChatView (`chat.py`)**: Логика и UI за чата.
  - **MemoryView (`memory.py`)**: Логика и UI за преглед на паметта.
  - **FilesView (`files.py`)**: Логика и UI за файловете.
  - **SettingsDialog (`settings_dialog.py`)**: Диалог за настройките (`Base URL`, проверка на връзката, име в чата, `user_id`).
- **`state/`**: Съдържа логиката за управление на състоянието на приложението (памет, файлове) и настройките. Настройките се управляват чрез Pydantic v2 (`pydantic-settings`) и се записват в локален JSON файл `settings.json`.
- **`tests/`**: Съдържа автоматизираните тестове.

## Локална среда за разработка

За да стартирате проекта локално за разработка, следвайте тези стъпки:

1. **Клониране на хранилището:**
   ```bash
   git clone <repository_url>
   cd <repository_name>
   ```

2. **Създаване на виртуална среда (препоръчително):**
   ```bash
   python -m venv venv
   source venv/bin/activate  # За Windows: `venv\Scripts\activate`
   ```

3. **Инсталиране на зависимости:**
   Инсталирайте проекта заедно със зависимостите за разработка:
   ```bash
   pip install -e .[dev]
   ```

4. **Стартиране на приложението:**
   Можете да стартирате Flet приложението, като изпълните главния Python файл:
   ```bash
   python main.py
   ```

## Правила за разработка

- **Мрежови заявки:** Всички HTTP заявки към бекенда задължително минават през `api/client.py`.
- **Тестване:** Тестовете не правят реални мрежови повиквания (използвайте мокове, напр. `respx`). Изпълнявайте тестовете чрез `python -m pytest` или `PYTHONPATH=. pytest`; CI ги пуска на Python 3.11 с `-W error::DeprecationWarning` (затова `requires-python` е `>=3.11`).
- **Качество на кода:** Преди всеки Pull Request, `ruff check --preview .` (линтер) и `pytest` (тестове) трябва да преминават без грешки.
- **Грешки и логове:** Грешките на приложението се записват локално в `app.log` с помощта на `logging.handlers.RotatingFileHandler`. Избягвайте използването на чист `print` за грешки.
- **Flet версия:** Версията на Flet е стриктно фиксирана на `0.24.0`. Диалозите и SnackBar компонентите трябва да се управляват чрез `page.open()` и `page.close()`.

## Логове

Приложението е конфигурирано да записва грешки (и друга важна информация) локално във файл `app.log` в основната директория. Използва се `RotatingFileHandler` (макс. 1MB на файл, до 3 архива), за да се предотврати безкрайно нарастване на лог файла. Всички нови компоненти и логика трябва да използват `logging.getLogger(__name__)` и да логват съответните грешки, вместо да използват `print()`.

## Билдване на самостоятелно приложение

За да компилирате проекта в самостоятелно изпълнимо десктоп приложение (`.exe` за Windows, `.app` за macOS), използвайте командата за билд на Flet.

Изпълнете следната команда от основната директория на проекта:

```bash
flet build <target_platform>
```

Заменете `<target_platform>` с желаната операционна система (напр. `windows`, `macos`, `linux`).

Пример за macOS:
```bash
flet build macos
```

Пример за Windows:
```bash
flet build windows
```

Резултатният изпълним файл ще бъде запазен в директорията `build/` (или подобна, в зависимост от целевата платформа).
